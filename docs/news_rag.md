# News-RAG: контракт интеграции

Статус: черновик для первого baseline.

## Назначение и границы

News-RAG формирует новостной контекст к дате опроса и передаёт его в
существующий `NewsPromptBuilder`. Профили RLMS-HSE, исполнение опроса и
eval-harness остаются без изменений, если не блокируют интеграцию.

Первый baseline работает на исходных новостях. Entity neutering на этом этапе
не применяется.

## Источник данных

- Переиспользуется существующий Telegram-корпус без повторного сбора и миграции.
- 12 каналов, около 983 тыс. валидированных сообщений, начало периода — март
  2016 года.
- Эмбеддинги FRIDA, 1536 измерений, хранилище `sqlite-vec`.
- Перед первым экспериментом фиксируется машинный manifest: идентификатор или
  hash корпуса, диапазон дат, число сообщений, схема и версия эмбеддингов.

## Временная семантика

- В retrieval допускаются только сообщения, опубликованные раньше cutoff.
- Cutoff задаётся явно и применяется до векторного поиска.
- Часовой пояс и правило включения сообщений за дату опроса должны быть
  зафиксированы до реализации.
- Текстовые периодные маркеры в первом baseline сохраняются.

## Retrieval baseline

1. Для каждой настроенной оси выполняется отдельный поиск.
2. Извлекаются `top_k = 50` сообщений на ось.
3. Почти дубли удаляются по cosine similarity `>= 0.9`.
4. Threshold-based отбор по релевантности не применяется: наблюдавшиеся
   распределения похожести унимодальны.
5. Для каждого результата сохраняются минимум `message_id`, `channel`,
   `published_at`, `text`, `score`, `axis` и позиция в выдаче.

Список осей и порядок межосевой дедупликации задаются конфигурацией и должны
быть утверждены отдельно.

## Суммаризация

Основной режим — два этапа:

1. отдельное саммари для каждой оси;
2. мета-нарратив по осевым саммари.

Для абляции должны поддерживаться как минимум режимы `raw` и `two_stage`.
One-shot суммаризация не является baseline.

## Контракт с существующим кодом

`NewsPromptBuilder.buildPrompt(surveyDate, profile)` остаётся внешней точкой
интеграции и возвращает строку для секции `Новости`.

Внутренний news-RAG получает дату опроса и конфигурацию, а возвращает
структурированный `NewsContext`, из которого builder формирует текст промпта.
Зависимость retrieval от полей профиля не добавляется без отдельного решения.

Отключение news-RAG должно быть явным параметром эксперимента. Ошибка retrieval
не должна незаметно превращать эксперимент `news` в `no-news`.

## Проверка первого baseline

- Ни один документ не пересекает cutoff.
- Дедупликация детерминирована на golden fixture.
- Повторный запуск с тем же manifest и config даёт ту же выдачу.
- Секция `Новости` корректно собирается для `raw` и `two_stage`.
- Минимальная абляция: `no-news` / `raw` / `two_stage`.

## Артефакты прогона

- `config`: параметры retrieval и суммаризации;
- `corpus_manifest`: версия входного корпуса и эмбеддингов;
- `run_manifest`: commit, config, модели, периоды и seed;
- `metrics`: результаты после подключения рабочего eval-harness.

Большие воспроизводимые retrieval-выдачи и саммари в Git не коммитятся.
