# newsDB

Новостные данные проекта: общий корпус и проектная база результатов.

```
newsDB/
├── project.db            результаты пайплайна, чтение и запись
├── corpus.db → ~/workspace/amnesiacDB/corpus.db   новости, только чтение
├── migrations/           DDL проекта, с номера 012
├── SCHEMA.md             схема project.db
└── MANIFEST.yaml         состав этой копии, происхождение, ловушки
```

Схема корпуса здесь не дублируется — она в `~/workspace/amnesiacDB/SCHEMA.md`,
там же `MANIFEST.yaml` корпуса и его миграции.

## Как открыть

Две базы — два соединения. Джойнов между ними нет, `ATTACH` не нужен.

```python
import sqlite3, sqlite_vec

project = sqlite3.connect("data/newsDB/project.db")

corpus = sqlite3.connect("file:data/newsDB/corpus.db?mode=ro", uri=True)
corpus.enable_load_extension(True)
sqlite_vec.load(corpus)
corpus.enable_load_extension(False)
```

Без `sqlite_vec.load()` корпус не читается **вообще**: в схеме есть виртуальная
таблица, и SQLite падает с `no such module: vec0` на любом запросе, даже к
`messages`.

Читать корпус удобнее через готовое вью, оно само делает правильную склейку и
отсекает невалидные сообщения:

```python
rows = corpus.execute("""
    SELECT message_id, channel, date, processed_text, embedding
    FROM message_embeddings
    WHERE date >= ? AND date < ?
    ORDER BY date, message_id
""", (
    "2023-04-16T21:00:00+00:00",
    "2023-04-30T21:00:00+00:00",
)).fetchall()
```

Границы соответствуют полуночам 17 апреля и 1 мая по Москве. Правило см. в
пункте 1 раздела «Три ловушки» ниже и в [SCHEMA.md, «Окно сбора»](SCHEMA.md#окно-сбора).

`embedding` — сырые байты, 1536 × float32 little-endian:
`np.frombuffer(blob, dtype="<f4")`.

## Что нужно кроме этих файлов

- **`sqlite-vec`** — обязателен, см. выше. В `pyproject.toml` уже есть.
- **`amnesiac[select]`** — `select_by_axis` для отбора, `summarize_axes` и
  `summarize_meta` для суммаризации. Подключён пином на тег `v0.2.0`
  (коммит `c26be79`), `uv.lock` фиксирует разрешённый коммит; рабочее дерево
  `~/workspace/amnesiac` в путь сборки не входит (D-008). Обновление —
  осознанная правка `pyproject.toml`, а не побочный эффект работы в соседнем
  каталоге.
- **`OPENROUTER_API_KEY`** в окружении — для вызовов LLM. Ключ из переменной
  окружения, не из файла в репозитории.
- **Infinity с FRIDA — не нужен.** Девять осей уже посчитаны и лежат в корпусе
  (`дкп`, `инфляция`, `продовольствие`, `курс`, `тарифы`, `зарплаты`, `труд`,
  `кризис`, `бюджет`), и менять их формулировки мы не собираемся: текст запроса
  входит в `query_hash`, то есть в ключ вектора (D-014). Сервис понадобится,
  только если заведёте свои оси — их запросы надо эмбеддить той же моделью
  `ai-forever/FRIDA` с префиксом `search_query: `, иначе векторы несовместимы с
  документами. Эмбеддить документы не нужно — они уже в корпусе.
- **Конфиг**: `NewsLogic/NewsRagConfiguration.py` — оси и их порядок,
  `horizon_days`, `top_k_per_axis`, `dedup_threshold`, исключённые каналы,
  модель суммаризации и пин провайдера.

## Три ловушки

1. **Окно задаётся в московском времени.** Это `[run_date - horizon_days, run_date)`:
   `horizon_days` полных московских суток до дня опроса, сам день опроса исключён
   целиком. **Прежняя ловушка инвертирована:** голые календарные даты дают неверное
   окно со сдвигом на три часа — захватывают `00:00–03:00 MSK` дня опроса и
   теряют те же три часа в начале. UTC-форма и правило покрытия — в `SCHEMA.md`,
   раздел «Окно сбора».
2. **Вектор оси выбирайте по полному ключу** `(axis, query_hash,
   embedding_model, dimension)`, а не по одному имени. Кеш `query_vectors`
   общий на все проекты, одноимённые оси с разными запросами лежат рядом;
   промахнётесь — найдётся чужой вектор, молча.
3. **Порядок осей значим.** Он определяет порядок блоков мета-промпта, а держится
   только порядком литералов в конфиге. Досчитывая хвост осей к кешу, собирайте
   словарь явно — `{name: ready[name] for name in axes}`; наивное объединение даёт
   другой промпт при тех же данных.

Перед использованием векторов сверьте контракт корпуса:

```sql
SELECT key, value FROM corpus_meta;
```

Если `embedding_model` или `embedding_input` не те, что ждёт ваш код, векторы
несовместимы — внешне это никак не проявится.

## Состояние базы

`summaries` и `axis_summaries` пусты: кеш очищен целиком по D-026, потому что
всё в нём было посчитано по прежнему UTC-окну, а ключ
`(run_date, horizon_days, model)` не отличает такие строки от новых. Первый
прогон считает серию с нуля.

`infom_expectations` (157 строк) оставлена — это целевой ряд для контура оценки,
взять его заново неоткуда.

`neutered_summaries` и `forecasts` удалены миграцией `014`: это результаты
blind_prophet, они живут в базе того проекта.
